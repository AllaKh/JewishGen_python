## Проект

Python-скрапер для генеалогического поиска. Лончер (`app.py` → `gui/launcher.py`) с карточками баз.  
Интегрированные скраперы: **JewishGen**, **FamilySearch**, **MyHeritage**, **АИС Скарб**. Остальные базы — ссылкой в браузер.  
Стек: Playwright (async), PySide6 GUI, python-docx, openpyxl.

## Правила работы с git

- **Никогда не делай `git add -A` или `git add .`** — только конкретные файлы.
- **Перед коммитом** убедись что файл действительно содержит нужные изменения.
- **Revert — опасная операция**: `git revert HEAD` откатывает к последнему _закоммиченному_ состоянию, а не к тому что было в working copy до твоего коммита. Если до твоего коммита были незакоммиченные изменения пользователя — они войдут в твой коммит. Revert их сотрёт. В таком случае нужно делать `git revert HEAD` (revert of revert), чтобы вернуться к своему коммиту, а потом точечно откатить только свои правки.
- **Коммить только то, что просит пользователь.** Не коммить сам по себе.

## FamilySearch — алгоритм скрапера (строго соблюдать)

1. Открыть домашнюю страницу → заполнить First Names, Last Names (+ Place, Birth Year) → SEARCH.
2. Нажать таб Historical Records `[data-testid="hr-tab"]`. URL → `?tab=records`.
3. **Логин НЕ нужен** для показа строк таблицы HR tab. Строки видны без логина.
4. Собрать строки таблицы `tbody tr`. Если 0 строк — **не добавлять логин**, а увеличивать таймауты ожидания (XHR грузится медленно).
5. Открыть первую запись → если редирект на логин → залогиниться **один раз**.
6. Логин определяется по: `"login" in page.url` **ИЛИ** `"sign in" in page.title()` (JS-редирект может не завершиться до domcontentloaded).
7. После логина — `logged_in_ref[0] = True`. Повторный логин не делать.
8. Все записи открывать на **одной** странице (`page.goto(url)`), не в новых вкладках.
9. После каждой записи возвращаться на `results_url` через `page.goto(results_url)`.
10. Если есть Advanced Search — после первой записи: **обязательный reload**, HR tab, Advanced Search попап, заполнить поля, нажать Search, заново собрать результаты.

## FamilySearch — скачивание JPG

- **`expect_download` должен оборачивать ВЕСЬ блок**: первый клик на download кнопку + выбор JPG Only + клик confirm. Иначе если первый клик сам инициирует загрузку — событие пропускается.
- После клика на картинку — ждать `button[aria-label*="Download" i]` до 8 секунд перед тем как пробовать fallback-селекторы. После логина viewer грузится медленнее.
- Записи с `view=index` в URL — индексные, без изображения документа. Не вызывать `_download_jpg`, только сохранить thumbnail.
- Если `_best_img(page)` вернул пустую строку — не вызывать `_download_jpg` вообще.
- Таймаут `expect_download` — 45 секунд.
- Fallback если timeout: ждать 15 секунд появления файла в папке Downloads.

## FamilySearch — логин

- Форма: `#userName`, `#password`, `#login`
- Заполнять через `page.fill()` с retry до 3 раз (React-форма может сбрасывать значение)
- Ждать 2 секунды после появления `#userName` перед заполнением
- После `#login` — ждать редирект на `familysearch.org` без `login` в URL (таймаут 30 сек)

## Что НЕЛЬЗЯ делать

- **НЕ добавлять логин перед сбором результатов** — FamilySearch показывает строки таблицы без логина. Логин только при открытии первой записи.
- **НЕ использовать `.first` для полей семейных членов** — после раскрытия секции Spouse появляются новые поля с такими же плейсхолдерами как у предка. `.first` заполнит поля предка, а не супруга. Использовать `data-testid`.
- **НЕ использовать `button:has-text("Search")` для кнопки в попапе Advanced Search** — это может совпасть с другими кнопками. Использовать `[data-testid="search-button"]`.
- **НЕ делать поспешных выводов** о причине ошибки. "Строк: 0" — скорее всего медленный XHR, а не проблема с логином.

## JewishGen scraper (jewishgen_scraper.py)

Переименован из `scraper.py`. GUI-файл `gui/jewishgen.py` импортирует `jewishgen_scraper as scraper`.

### Скачивание изображений из результатов JewishGen

Анализируется **последний столбец** каждой строки результатов:

| Что в ячейке | Действие |
|---|---|
| Текст начинается с `FHL` (ссылка) | FamilySearch microfilm → открыть вьюер на нужном снимке, скачать |
| Число ≥ 100 000 (большое) | Archive ref — НЕ открывать, ссылка уже в таблице |
| `2423962/3` или `2423962 / 3` (дробь) | То же — НЕ открывать |
| Число < 100 000 в виде `[398]` или `398` | Кликнуть, скачать изображение |

Также проверяется **предпоследний столбец**: если там кликабельное слово `Image` → кликнуть, скачать.

### FamilySearch microfilm viewer — ПРАВИЛЬНЫЙ алгоритм

**Главный урок**: НЕ заполнять input-поле (кириллический селектор ненадёжен).  
Использовать URL-параметр `?i=N` (0-based индекс):
- Снимок 61 → `?i=60`
- Снимок 218 → `?i=217`

```python
base_url = fs_url.split("?")[0]
target_url = f"{base_url}?i={img_num - 1}"
```

**После навигации на `?i=N`:**
- Ждём до 30с появления `img[src]` count > 5 (признак загрузки сетки)
- Если логин → заходим → FamilySearch редиректит обратно на `?i=N` через `state=` параметр
- Если редирект потерял `?i=` → навигируемся вручную на `target_url`
- Thumbnail N уже подсвечен синим → кликаем его → скачиваем

**Браузер для FHL**: отдельный (`async with async_playwright()`) с теми же флагами что FamilySearch scraper:
```python
args=["--start-maximized", "--disable-blink-features=AutomationControlled"]
no_viewport=True, accept_downloads=True
```
Если использовать JewishGen-контекст → FamilySearch выдаёт "Access Denied / Error 15".

## АИС Скарб (skarb_scraper.py + gui/skarb.py)

Сайт `https://archiveskarb.by/db/`. **Логина нет.**

- **Параметр поиска: `q`** (НЕ `ФИО`!). HTML: `<input type="text" name="q">`. Поиск нескольких фамилий через ` или `.
- **Ссылки записей**: `a[href*="ELEMENT_ID"]` (формат `/db/?ELEMENT_ID=275117`). Собирать через JS — надёжнее, чем `query_selector_all`.
- **Пагинация**: `a.modern-page-next` (текст «След.»). Брать href через JS, ходить по всем страницам.
- **Имя персоны**: из текста ссылки в результатах поиска (`row["name"]`), НЕ из `<h1>` страницы записи — там «АИС Скарб» (шапка сайта).
- **Поля записи**: JS-экстрактор пар «Метка: значение» (dl/dt-dd, таблицы, `<b>метка</b> значение`, текстовые строки).
- **Word/Excel**: ссылка-источник в КОНЦЕ записи; в Excel колонки `#, Имя, <поля>, Фото, URL`.

## MyHeritage (myheritage_scraper.py + gui/myheritage.py) — самый сложный

### Антибот: ТОЛЬКО персистентный профиль
- `launch_persistent_context(MH_PROFILE_DIR=".mh_profile")` — НЕ свежий контекст!
- Свежий контекст без cookies → MyHeritage флагует логин как suspicious и шлёт challenge-письмо «Confirm a login attempt».
- После первого успешного входа сессия запоминается, 2FA больше не спрашивает.
- Персистентный профиль **восстанавливает старые вкладки** при старте — закрывать все кроме одной.

### 2FA по почте (КЛЮЧЕВЫЕ уроки)
- MyHeritage шлёт **ДВА письма с РАЗНЫМИ кодами**:
  - **B** «Ваш код подтверждения для входа / verification code» — это код для поля «Введите верификационный код» (приоритет!)
  - **A** «Confirm a login attempt» (анти-фрод, flagged as suspicious) — запасной
  - Читать ОБА, пробовать B потом A.
- Чтение кода — **браузером, новой вкладкой** `mail.yandex.ru` (поле «Mail password» в GUI = пароль того же ящика, что логин MH):
  1. `#header-login-button` («Войти»)
  2. `input[autocomplete="username"]` → email
  3. `button[data-testid="add-user-next"]` (Next)
  4. span «Log in with your password»
  5. `input[autocomplete="current-password"]` → пароль
  6. **НЕ открывать верхнее письмо** (там реклама hh.ru!) — сканировать текст инбокса регуляркой `confirmation code in the login screen: (\d{6})`, брать письмо MyHeritage
- Перед вводом кода: `page.bring_to_front()` (вкладка почты была в фокусе, иначе ввод уходит «в никуда»).
- Кнопка подтверждения называется **«Отправить»** (НЕ «Авторизация» — это фоновая кнопка формы логина!). Искать внутри **модалки с полем кода** (поднять от поля кода к `[role=dialog]`/`.modal`/`form`, кликнуть кнопку внутри).
- **ОДИН** submit! Enter + клик одновременно → MyHeritage делает resend (новый код), старый аннулируется → пустые поля + таймер. Проверять результат до 18с, не отправлять повторно.

### После логина
- Сессия из профиля → редирект `/login` → главную семейного сайта. Если URL не `/login` → уже залогинены, форму логина НЕ искать.
- Страница выбора сайта `FP/select-site.php`: парсить `goToSiteClicked('ID','URL')`. Если уже на `family-sites/<slug>/<ID>` → достать ID из URL.
- URL поиска: `research?s=<ID>&lang=RU`.

### Язык запроса = язык сайта (КРИТИЧНО — не путать с языком GUI)
- Язык, на котором значения уходят в MyHeritage, определяется **селектором `f_site`** (`SITE_MAP` → `lang=` в URL), а **НЕ подписями GUI**.
- Если выбран русский сайт (`lang=RU`) → все **значения-данные запроса** должны быть **русскими**: `record_type` («Все записи»/«Исторические записи»/«Семейные деревья»), `category`, лейблы клик-фильтров. Иврит → иврит, и т.д.
- **«Хром» GUI можно держать английским** (плейсхолдеры, подписи `First name:`, `Birth year:`) — он НЕ уходит в запрос. Рабочее состояние = английский хром + **русские значения данных**.
- **ОШИБКА, которую я допустил**: перевёл на английский сами `RECORD_TYPE_OPTIONS`/`CATEGORY_OPTIONS` (данные!) → рассинхрон с русским сайтом → поиск дал **0**. Лечится возвратом значений на язык сайта.
- `_RT_MAP` в скрапере держать **двуязычным** (принимать и русские, и английские метки) — тогда смена языка GUI не ломает маппинг.
- TODO (другие языки): связать `f_site` → код языка → подписи `record_type`/`category` в GUI + язык клик-фильтров переключаются автоматически.

### Форма поиска
- Форма может быть в **iframe** — искать во всех `page.frames`.
- Если селекторы инпутов не совпадают — **разметить от кнопки «Поиск»**: подняться к контейнеру формы, пометить текстовые инпуты `data-pw-rf=first/last/year/place` по `data-automations`/плейсхолдеру/порядку, печатать через `page.keyboard`.
- «+ Больше» (advanced) открывать ТОЛЬКО если задан advanced-параметр.

### Результаты
- Открываются в **НОВОМ табе** — опрашивать `ctx.pages` до 25с, искать новую myheritage-вкладку с `research` в URL.
- **Кол-во на страницу**: `[data-automations="selector_header_container"]` → выбрать 50.
- **Пагинация**: `a[data-automations="next_icon"]` — кнопка БЕЗ текста (только иконка)! Текстовый матчер её не видит. Кликать по data-testid, проверять что первая ссылка `showRecord` сменилась.
- **Ссылки записей**: `a[href*="showRecord"]`, имя + % из карточки.
- **Разделитель «расширения критериев»**: собирать только записи **ДО** него (после — нерелевантные). Искать **наименьший** элемент, чей текст содержит и «расширени», и «критери» (фраза разбита по спанам; leaf-only поиск не находит). `stop=True` как только разделитель найден → пагинацию прекратить.
- **Точный поиск — через URL `exactSearch=1`**, НЕ через чекбокс (галка `aria-checked` не переключается ничем). Перестроить URL результатов: заменить/дописать `exactSearch=1`, `goto`, дождаться появления `a[href*=showRecord]` (SPA рисует после XHR — `networkidle` мало).
- **`exactSearch=1` строг по ВСЕМ полям сразу**: запрос с отцом+супругом+годом смерти легко даёт **0 точных совпадений** (у записей эти поля пустые/иначе записаны). Поэтому: запоминать `_noexact_url`, и если точный поиск собрал **0** → откатиться на обычные результаты (первая страница, самые релевантные сверху, кап 40). Так поиск никогда не вернёт 0, если записи есть.
- **Диагностика при 0 собранных**: дамп `_diag_results` (url, title, счётчики `showRecord`/`recordTitle`/`anyRecord`/`resultCards`/`formInputs`, признак разделителя/«нет результатов», sample ссылок). Живой сайт мне недоступен (Chrome блокирует myheritage) — без дампа причину 0 не угадать, не гадать.

### Запись (`_detail`)
- Имя — h1 ближайший к строке «В категории» (НЕ имя из меню аккаунта «Алла Хананшвили»!).
- Поля — по **белому списку** генеалогических меток (Имя/Рождение/Смерть/Отец/Мать/Муж/...), иначе в таблицу лезет мусор из боковой панели «больше записей» (Geni).
- Ссылка «Посмотреть полный профиль на этом сайте» — искать по всей странице.
- **Фото — через лупу**: кликнуть `div.main_record_image_zoom` (`.searchMainSprite.imageZoom`) → откроется попап с **полным** фото; взять самое большое `<img>` по площади; закрыть попап (кнопка/Escape). Качать через `page.request.get` (НЕ новой вкладкой — иначе «Target page closed» на ~16-й записи). Полное фото — на диск, в Word — маленькое (`Inches(2.2)`).
- **WEBP→PNG для Word**: MyHeritage отдаёт фото в **WEBP**, python-docx его не умеет (`add_picture` молча падает). Конвертировать через Pillow (`_to_png`) перед вставкой; JPEG/PNG/GIF/BMP пропускать как есть.
- Исторические записи: полное фото требует Omni — только превью (thumbnail в Word).
